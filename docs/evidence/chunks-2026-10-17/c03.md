## Native PF2e source evidence

Fetched from `raw.githubusercontent.com/foundryvtt/pf2e/<ref>/…`. Refs: `master`, `pf2e-8.5.0` (installed target), `pf2e-8.4.1` (declared minimum in `module.json` `relationships.systems[0].compatibility.minimum`).

1. **`variantClone` (native NPC clone schema).** `src/module/actor/npc/document.ts`: master 561–576, 8.5.0 515–530, 8.4.1 515–530. It builds `changes = { name, system.details.publicNotes, img, prototypeToken.texture.src }` and returns `this.clone(changes, { save, keepId })`. The publicNotes line is `details: { publicNotes: params.description ?? source.system.details.publicNotes }`, which **replaces** the notes rather than appending.
2. **`VariantCloneParams`.** `src/module/actor/npc/types.ts` lines 29–38 (master and 8.5.0): `name`, `description`, `img {actor, token}`, `save`, `keepId`.
3. **`ActorPF2e.clone` override.** `src/module/actor/base.ts` 406–414 (8.5.0 and 8.4.1) copies dependent tokens only when `keepId` is set. master has no such override.
4. **NPC note fields.** `src/module/actor/npc/data.ts`: master 127/129/131, 8.5.0 and 8.4.1 128/130/132 (`blurb`, `publicNotes`, `privateNotes`).
5. **Create-time rewrite.** `src/module/actor/base.ts` 8.5.0 `createDocuments` 624–683 converts sources and sets default ownership and token flags (637–639). It calls `migrateActorSource` (679) before `super.createDocuments` (683). 8.4.1 and master have the same shape (master 643–710).
6. **Enricher patterns.** `src/scripts/hooks/init.ts`: master 134/141/146, 8.5.0 70/77/82, 8.4.1 70/77/82. They are `@(Check|Localize|Template)\[…\]`, `@(Damage)\[…\]`, and `\[\[\/(act) …\]\]`. **Every PF2e custom enricher requires a literal `[` or `[[`.** Foundry core's `@UUID`/`@Embed`/inline-roll forms are also bracket-delimited, but core source is not in this repository and was not fetched.

### Decisions from that evidence

- **The module does not call `variantClone`.** Its `save: true` path calls `clone` on `this`. For a compendium document, whether Foundry's `Document#clone` writes back to the pack could not be verified here, because core source is not in the PF2e repository. `variantClone` also replaces `publicNotes` wholesale, so appending needs composed text regardless. The module mirrors its `changes` set on a deep copy of the published source and verifies the result. Image and token texture are kept.
- **Flavor is appended** to `system.details.publicNotes` after the source notes, which remain the exact prefix. `blurb` and `privateNotes` are untouched.
- **Inert text.** The policy rejects `[`, `]`, and `@` followed by a word in AI text. Every enricher form needs a bracket, so the text cannot enrich. Accepted text is HTML-escaped with the shared `toHtml`/`esc`. Names also reject `<>{}@` and line breaks. `enrichDescription` and `art.mjs` are never imported, and a static regression asserts that.
- **Numeric guard.** Dice notation, `DC`/`AC`/`HP`, level and foot/feet numbers, and signed bonuses are rejected in flavor and biography. This is a filter, not a rules validator. The schema also has no numeric fields.

## Design

- **Output schema (strict).** Exactly `name`, `flavor`, `biography`, all strings. Limits are name 80, flavor 400, biography 2000, prompt 1000. Unknown keys are rejected, never ignored. A rejected reply is re-asked once through `requestJSON`'s existing structural retry.
- **Model context (whitelist).** Source name, rarity, size, traits filtered to slugs (max 12), and the plain-text blurb (max 400). Never sent: `publicNotes`, `privateNotes`, items, rules, levels, art, or any mechanical field. The GM direction is JSON-quoted data, and the system prompt forbids game statistics.
- **Exact source.** Accepts only `Compendium.<enabled bestiary pack>.Actor.<16-char id>`. The pack must be an enabled `bestiaryActors` source, the index entry must be `npc`, and the re-fetched `doc.uuid` must equal the input. World actors, disabled packs, and other types are refused before any spend.
- **Mechanical identity.** A canonical snapshot covers actor `type`, `system` (minus the notes this engine appends), `flags`, `effects`, and every embedded item's `_id`, `type`, `name`, `_stats.compendiumSource`, `system` (including `description.value` and rules), `flags`, and `effects`.
  - Before creation: exact equality between source and payload.
  - After creation: each source value must still be present and equal. Defaults Foundry adds are tolerated.
  - Notes: source text and enricher multiset must survive; flavor text must appear.
- **Stale baseline.** The plan stores the canonical snapshot, which includes `publicNotes` (the preview does not show notes, and the appended text is copied at commit). Any change after preview blocks creation with `stale-source`.
- **Commit boundary.** Accepts only a plan object issued by `prepareReskinPlan`. Order: authorize, cancel check, re-fetch and compare, precommit verify (no write), authorize again, cancel check, `Actor.create`, postcommit verify, cancel check. Any failure after the write deletes only the new actor. If that delete fails, the survivor is attached as `error.simplyPF2eRollbackActor`. The commit point is then passed, and `present(actor)` runs; its failure is returned as `presentationError` and never deletes the actor.
- **Usage.** The AI call's usage is reported once, on the plan (`plan.usage`). AI errors keep `usage` and `cancelled`. Commit spends nothing, and its errors carry `usage: null`.
- **Authorization.** A floor of `game.user.isGM === true` and `game.system.id === "pf2e"`, plus an injected `authorize()` that must return exactly `true`. There is no default and no bypass. The check runs before spend, again at commit, and again before the write.
- **Errors.** `ReskinError` carries a stable `code`. Messages are developer English; C04 maps codes to localized text. Cancellation uses the existing `SIMPLYPF2E.Errors.Cancelled` key.
- **Art.** Source `img` and token texture are kept. No image generation. The token label follows the new name.
- **Payload.** A deep copy of the published source without `_id`, `folder`, `ownership`, `sort`, or actor-level `_stats`. Item `_stats` is reduced to `compendiumSource`. Item `_id`s are kept so spell links and grants resolve. `Actor.create` runs with `{ keepEmbeddedIds: true, renderSheet: false }`.
- **Text normalization.** CRLF becomes LF before the plan is issued, because `toHtml` splits paragraphs only on `\n\n`.

## Exported API (contract for C04)

```text
ai.mjs
  generateReskinFlavor({ context, prompt, onProgress, signal })
    -> { flavor: { name, flavor, biography }, usage }

reskin.mjs
  RESKIN_CODES  // unauthorized | cancelled | invalid-prompt | invalid-source | invalid-output
                // | invalid-plan | stale-source | verification-failed
  class ReskinError extends Error  // { code, cancelled, usage, simplyPF2eRollbackActor? }
  listReskinSourceCandidates({ authorize })
    -> [{ uuid, name, packId, packTitle, level, rarity, size }]   // sorted; exact npc uuids only
  prepareReskinPlan({ sourceUuid, prompt, authorize, signal, onProgress })
    -> frozen plan (one provider call on success; no writes)
  reskinPlanPreview(plan)
    -> { sourceUuid, sourceName, name, flavor, biography, itemCount, sourceDigest, changes, usage }
  commitReskinPlan(plan, { authorize, signal, present })
    -> { actor, name, sourceName, itemCount, sourceDigest, presentationError }

reskin-policy.mjs  pure helpers (RESKIN_LIMITS, reskinOutputProblem, plainText, ...)
```

Integration assumptions C04 must satisfy:

1. `authorize` must return exactly `true` only when the experimental tool is enabled for this GM. The gate itself is C02's. This backend reads no settings for it.
2. Keep the **same plan object** from prepare through preview to commit. Plans are in-memory and are not persisted, so a reload requires a new prepare.
3. Serialize prepare and commit per UI, which is C04's busy lifecycle. Each call is independent and stateless otherwise.
4. Preview with `reskinPlanPreview` only, as plain text. Never render raw AI text as HTML.
5. Treat `error.cancelled === true` as cancellation. Map `error.code` to localized messages. If `error.simplyPF2eRollbackActor` is set, report the survivor and do not retry silently.
6. Show the usage from prepare once. Commit adds no provider usage.
7. Presentation (sheet open) goes in `present`. Do not delete the actor from presentation code.
8. State in the UI that mechanics are copied unchanged and only name and appended notes change.

## Remaining native QA (open, not claimed)

1. **Embedded id preservation.** The postcommit verifier matches items by `_id`, relying on `keepEmbeddedIds: true`. The PF2e sources fetched here never mention that option. The repo's own `scripts/post-create.mjs:139` warns that Foundry "is allowed to allocate embedded ids differently". Foundry core source is not in the PF2e repository, so the default was not verified. If ids change, every reskin with items blocks and rolls back safely. The remedy would be identity and link remapping, which is not implemented here.
2. **Foundry HTML sanitization on persistence.** Notes are compared as plain text plus enricher tokens, which tolerates normalization. Item `description.value` is compared exactly, so a sanitizer rewrite blocks creation.
3. **Create-time migrations** (`migrateActorSource`) on older bestiary packs. Sources that migrate fail closed. Coverage across enabled packs is unknown.
4. **Appended note rendering** in the NPC sheet: `h3`/`p` markup and no enricher output.
5. **Live provider behavior**, including a real mid-request cancel (no actor created, usage recorded) and one bounded flavor call per reskin. No provider call was made here.
6. **Stale detection** against a real compendium edit.
7. **Foundry core enricher syntax** (`@UUID`, `[[/r`) was not fetched from source. The inert policy depends on those forms being bracket-delimited.
8. C04 UI, localization, keyboard and screen-reader behavior, and the gate itself are outside this chunk.

## Known limits

- Flavor is cosmetic only. Mechanical text, including rule elements and `publicNotes` originals, is copied unchanged.
- The numeric filter is conservative and best-effort. It can reject legitimate wording that contains digits near stat words; the GM then re-prepares.
- Actor-level `flags` are kept as published. Any Foundry-set `core.sourceId` on the source is carried over.
- Sources that PF2e rewrites on create are refused rather than approximated, by design.
