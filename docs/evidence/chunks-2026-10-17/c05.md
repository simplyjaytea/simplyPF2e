# C05 — PC editing contract and recomputation

Status: implemented on worktree branch `t3/c05` (worktree `/home/jtf/.t3/worktrees/simplyPF2e/t3-c05`), based on integration HEAD `aeef8bb`. Pure contract only: no UI, no actor writes, no Foundry QA.

## Scope delivered

- **`scripts/pc-edit.mjs`** — `applyPCEdit(plan, edit, { catalogs, services })` and `validatePCEditCompletion(plan)`.
  - Plan shape: `{ concept, resolved, pending }`. Every call returns a new plan; the input is never mutated.
  - Exact identity edits (`ancestry`, `heritage`, `background`, `class`, `classPath`) accept only offered, issued candidates (`isIssuedCandidate`), loaded through the real document service and type/eligibility checked.
  - Plain edits: `keyAbility` (must be legal for the current class) and `backgroundLore` (must be a current background option).
  - `feat` swaps one slot's pick from its offered candidates; duplicate names are refused.
  - `equipment` swaps one line's exact catalog entry, re-resolved through `resolveEquipment(…, { exactContent: true })`.
  - Dependent invalidation: changing ancestry drops a heritage that no longer fits; changing background drops its lore choice and sets a lore pending when the new background needs one; changing class drops a class path and an illegal key ability and sets them pending. Pending choices block further identity edits and completion.
  - Identity edits recompute ABC documents, feat slots and traits through `resolvePCConcept`, then remap existing feat picks to the new slots. A pick survives only if its exact candidate is still offered; otherwise it is reported in `invalidated`.
  - Unchanged selections return `changed: []` and preserve the plan.
  - `validatePCEditCompletion` is in memory: pending choices, `assertPCIdentity` against `requiredIdentity`, feat picks against current candidates, duplicate feat names, and `completionManifest`. It writes nothing.
- **Spell editing is deferred.** `spells`, `focusSpells`, and `spellcasting` edits refuse with `PC_EDIT_DEFERRED`. Any identity edit on a character that already has spells is refused the same way. No spell edit path exists.
- **`scripts/pc-edit.test.mjs`** — regression with injected services and issued candidates: feat swap and input immutability, refusal paths, equipment swap and gp recomputation, class-change invalidation and pending resolution, key-ability and lore refusals, completion validation.
