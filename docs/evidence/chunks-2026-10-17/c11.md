# C11: Level-shifting implementation (experimental)

## Scope
Implements the C10 design for an experimental, GM-only tool that creates a new world NPC shifted to a different level. No UI in this chunk; the UI belongs to C04.

## Approval assumption
C10 lists six open approval items and states C11 must not start until approved. This chunk was dispatched with the instruction to implement the C10 design. It uses C10's recommended options:
- Supported deltas: −2, −1, +1, +2. Larger shifts are rejected.
- Narrow caster policy: damaging spells rejected, non-innate spell rank capped at ceil(T/2), level ≤ 0 casters rejected.
- Abilities unchanged; skills shifted.
- First-instance Strike damage shifted.
- Name "<name> (Level T)"; provenance appended to publicNotes.

Main should confirm these before relying on the feature.

## Files
- `scripts/level-shift-policy.mjs`: pure planning, classification, damage transform, caster rules, clone builder, verifier. No Foundry globals.
- `scripts/level-shift.mjs`: gate at every entry, before the write, and before rollback; stale-source check; `Actor.create(…, { keepEmbeddedIds: true, renderSheet: false })`; post-write verify; rollback delete of only the new actor; survivor reporting.
- `scripts/level-shift-policy.test.mjs`, `scripts/level-shift.test.mjs`: stubbed globals, no live world.

## Tests
Policy: round trip 5→6; range and shift limits; adjusted, segmented, non-NPC, Strike-less rejection; extreme→high HP mapping; spell DC unclassified; caster damage, over-cap, innate exemption, level 0; flat damage shift and round trip; exclusions unchanged and source not mutated; clone fields; tamper detection.
Wiring: refusal when disabled, not GM, wrong system; gate revoked between preview and write; stale source; verification failure deletes only the new actor; rollback refusal reports the survivor; successful create leaves source unchanged.
