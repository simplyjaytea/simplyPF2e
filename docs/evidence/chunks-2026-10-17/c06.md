# C06 — PC editor UI integration

Status: implemented on worktree branch `t3/c06` (worktree `/home/jtf/.t3/worktrees/simplyPF2e/t3-c06`), based on integration HEAD `3c5b914` (includes C05). No native Foundry QA has been run.

## Scope delivered

- **Editable PC preview.** The Character preview renders one control per editable choice: ancestry, heritage, background, class, class path, key ability, background lore, each feat slot, and each equipment line. Each control has its own Apply button (`data-action="applyPCEdit"`, `data-control`); there is no change-on-select, so a draft survives until it is applied or invalidated.
- **Current eligible catalogs.** Options come from the identity catalogs already used by the required-choices panel. Heritage is narrowed to the selected ancestry (`heritageMatchesAncestry`). Class paths are filtered to the selected class. Feat options are the slot's offered candidates. Equipment options are `getEquipmentCandidates` at the PC level.
- **One catalog set.** The same catalogs object feeds the displayed options and `applyPCEdit`, so the UI offers only what the contract accepts.
- **Errors.** Contract refusals (`PC_EDIT_*`) show their message in `#pc-edit-status` (`role="alert"`). Unexpected failures show a localized generic message and log to the console. A refused edit keeps every draft for correction.
- **Retained drafts.** Form values are read into drafts before each apply. A successful apply consumes the applied control's draft and the drafts of every control in `invalidated`. Other drafts survive.
- **Commit gating.** The Create button is disabled, with `aria-describedby` pointing to the blocker list, whenever `validatePCEditCompletion` is not complete or an edit is in flight. `#createCharacterActor` fails closed on the same condition before any native write, using `SIMPLYPF2E.PCEdit.CreateBlocked`.
- **Spell edits deferred.** Spell-affecting edits are refused by the contract (`PC_EDIT_DEFERRED`). The UI shows a `spellsDeferred` note when the plan has spells or focus spells.
- **Stale cache reset.** Every site that replaces the PC plan (`#pcResolved` assignments) calls `#resetPCEdit()`, clearing drafts, errors, and notices.

## Experimental gate

No new PC-editing gate is added. The C06 brief names none. The existing guards on native write paths are unchanged. The create gate is added inside `#createCharacterActor`, which is the native write entry point for Character mode.

## Known limitations

- **Equipment candidates are capped.** `getEquipmentCandidates` returns at most 120 entries ordered by level, then name. An equipment line whose current item is outside that list shows the placeholder option. Choosing a replacement from the visible list is still possible, but the current item cannot be re-selected once it falls outside the cap.
- **Spell edits are refused** by the contract and not offered in the UI.

## Error codes

Exported from `scripts/pc-edit.mjs` as `PC_EDIT_CODES`: `PC_EDIT_INVALID`, `PC_EDIT_UNSUPPORTED`, `PC_EDIT_DEFERRED`, `PC_EDIT_PENDING`, `PC_EDIT_UNRESOLVED`, `PC_EDIT_DUPLICATE`. The UI shows the message for any code starting with `PC_EDIT_`.
