### 9.2 Mechanism: cancel one document through a public hook

A temporary GM-console harness registers `Hooks.on("preCreateItem", …)` and returns `false` for exactly one item: the first item written to the second actor that the attempt creates. Member 1 is therefore complete and persisted before the cancellation. If Foundry cancels silently, as this design assumes (caveat below), the write sequence continues until post-create verification finds the missing item. That exercises the real rollback branch after earlier writes have persisted. The harness unregisters with `Hooks.off` and fires only once.

Why this mechanism: it uses no function wrapping, no shipped setting and no module change. The module already uses `Hooks.on` for render, document and system events (`simplypf2e.mjs:93`, `:104`, `:120`, `:145`).

Caveat: the cancellation contract (returning `false` cancels that document without an exception, and the hook argument order) is Foundry core behavior that this environment did not verify. The self-check in §9.4 must verify it before any scenario runs.

### 9.3 Draft sketch (not executed; not for the module)

```js
// C01 DRAFT: temporary GM-console harness. Not shipped. Do not run before the §9.4 self-check.
const armed = new Set(game.actors.contents.map((actor) => actor.id)); // actors before Create
const attemptActors = []; // actors created by the attempt, in creation order
let fired = false;
const cancelSecondActorFirstItem = (document) => {
  const parent = document.parent;
  if (!(parent instanceof Actor) || armed.has(parent.id)) return undefined;
  if (!attemptActors.includes(parent.id)) attemptActors.push(parent.id);
  if (fired || attemptActors.length !== 2 || parent.id !== attemptActors[1]) return undefined;
  fired = true;
  console.warn("C01 harness: cancelling first item of member 2:", document.name);
  return false;
};
Hooks.on("preCreateItem", cancelSecondActorFirstItem);
// …run Create through the normal UI and record the outcome…
Hooks.off("preCreateItem", cancelSecondActorFirstItem); // then confirm an unrelated item still creates normally
```

### 9.4 Self-check (must pass before any scenario)

A single probe actor, `C01 Probe`, is a new QA document created and deleted by this check. The probe hook cancels only items whose names match the probe pattern.

1. Create the probe with `Actor.create({ name, type: "npc", items: [A, B] })`, cancelling only item `C01 Probe B`. Expected: the probe persists with item A only, and no exception. This covers items written with the actor.
2. On the same probe, call `createEmbeddedDocuments("Item", [C])`, cancelling item `C01 Probe C`. Expected: no item C and no exception. This covers writes to an existing actor.
3. Unregister the hook, then create item `C01 Probe D`. Expected: it persists.

## Appendix A — parity script

Saved at `/tmp/c01-scripts/verify-release-parity.sh` for this run. Usage: `bash verify-release-parity.sh <assets-dir> <version> <commit> <repo-dir>`. It creates new directories under `/tmp`, does not modify the repo, and exits non-zero on the first mismatch.

```bash
#!/usr/bin/env bash
# Rebuild the expected release archive from a merge commit, mirroring
# .github/workflows/release.yml (stamp module.json, then zip the same file list),
# and compare it with downloaded release assets. Usage:
#   verify-release-parity.sh <assets-dir> <version> <commit> <repo-dir>
set -euo pipefail

assets=$1
version=$2
commit=$3
repo=$4
tag="v$version"
slug=simplyjaytea/simplyPF2e
manifest="https://github.com/${slug}/releases/latest/download/module.json"
download="https://github.com/${slug}/releases/download/${tag}/module.zip"

src=$(mktemp -d /tmp/c01-merge-src.XXXXXX)
exp=$(mktemp -d /tmp/c01-expected-zip.XXXXXX)
rel_x=$(mktemp -d /tmp/c01-release-extract.XXXXXX)
exp_x=$(mktemp -d /tmp/c01-expected-extract.XXXXXX)
echo "src=$src exp=$exp rel_x=$rel_x exp_x=$exp_x"

# 1. Committed tree at the merge commit (no .gitattributes export-ignore rules in this repo).
test ! -e "$repo/.gitattributes"
git -C "$repo" archive "$commit" | tar -x -C "$src"

# 2. Stamp version/manifest/download exactly as the workflow's jq step does.
(cd "$src" && jq --arg version "$version" --arg manifest "$manifest" --arg download "$download" \
  '.version = $version | .manifest = $manifest | .download = $download' module.json > module.json.tmp && mv module.json.tmp module.json)
cmp "$src/module.json" "$assets/module.json"
echo "PASS module.json asset is byte-identical to the stamped merge module.json"

# 3. Same file list as the workflow's "Build module archive" step, zipped from the stamped tree.
(cd "$src" && printf '%s\n' module.json LICENSE README.md && find lang scripts styles templates -type f ! -name '*.test.mjs' -print | sort) > "$exp/file-list.txt"
mapfile -t files < "$exp/file-list.txt"
(cd "$src" && zip -q "$exp/module.zip" "${files[@]}")
echo "expected archive entries: $(unzip -Z1 "$exp/module.zip" | wc -l)"

# 4. Entry listings must match (sorted; archive order is not significant).
diff <(unzip -Z1 "$assets/module.zip" | sort) <(unzip -Z1 "$exp/module.zip" | sort)
echo "PASS release archive entry list equals expected list ($(unzip -Z1 "$assets/module.zip" | wc -l) entries)"
if unzip -Z1 "$assets/module.zip" | grep -Eq '(^|/)[^/]+\.test\.mjs$'; then echo "FAIL test file in release archive"; exit 1; fi
echo "PASS no *.test.mjs entries in release archive"

# 5. Extract both archives into fresh directories; every file must be byte-identical.
unzip -q "$assets/module.zip" -d "$rel_x"
unzip -q "$exp/module.zip" -d "$exp_x"
diff -r "$rel_x" "$exp_x"
echo "PASS every extracted file byte-identical to the merge tree ($(find "$rel_x" -type f | wc -l) files)"
cmp "$rel_x/module.json" "$assets/module.json"
echo "PASS archive-internal module.json equals module.json asset"
echo "stamped fields (version, manifest, download):"; jq -r '[.version, .manifest, .download] | @tsv' "$assets/module.json"
if cmp -s "$assets/module.zip" "$exp/module.zip"; then echo "zip container bytes: identical to rebuilt zip"; else echo "zip container bytes: differ from rebuilt zip (container timestamps/order); entry-level parity above is the criterion"; fi
```
