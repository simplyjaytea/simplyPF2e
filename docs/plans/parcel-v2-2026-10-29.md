## Decisions

1. **Coin UUIDs have one owner.** `COIN_UUIDS` (full UUIDs, in `scripts/loot-actor.mjs`, where the drift check can see them) is the only table. `coinEntry(denomination)` derives the `{ packId, _id }` lookup that `builder.mjs` passes to `getDocument`. `builder.mjs` no longer holds bare ids. `loot-actor.mjs` was chosen because it is a leaf module (it imports only `text.mjs` and `reskin-policy.mjs`), so the import adds no cycle.
2. **Currency split is a module convention, with a threshold (part 2 decision).** A remainder under 100 gp is never paid in pp: 40 gp stays 40 gp. From 100 gp up, whole pp come first: 175 gp is 17 pp and 5 gp, and 320 gp is 32 pp. The rates are pf2e's `values.ts` 46-53. A fraction such as 0.37 gp lands in sp and cp, and any amount finer than 1 cp throws. Part 1 used no threshold (40 gp was 4 pp); part 2 changed it on the Lead's decision.
3. **All-or-nothing currency.** Each denomination is cloned from its pinned UUID. If any coin fails to load, the whole currency is dropped with the existing `CurrencyDrop` warning, so the loot actor never holds a partial total.
4. **Dropped ids are shown only for the two drops that `selectParcelSpells` makes:** an unknown slot id and an unknown spell id. The AI's string is capped at 60 characters, passed as data, and printed with `{{this}}`, so the template escapes it. Duplicate-slot and rank-above drops keep their fixed text, because they come from `assignParcelPicks`, which has no id to show.
5. **Merchant is opt-in.** The `lootSheetType` control sits in the same `showContainer` block as the loot-actor name, so it is visible only when the gate is on and a loot actor is the destination (for a parcel, always). `buildLootActorSource` defaults to `"Loot"` and refuses any other value, including `null`. With the gate closed, `#readForm` always returns `"Loot"`.

## Decisions that need the user

- **Pp threshold** is now 100 gp (the Lead's decision, recorded above). It applies to the coin remainder after a valuable is taken out, not to the whole table amount. Confirm this if the GM expects a different cut-off.
- **GM Core's currency text** was not fetched in this session. The rates are pf2e's and the split is the module's convention. Confirm that is the rule you want.

## Part 2: permanent slots, generic wands, valuables (2026-10-29)

Built against the part 2 spec (Product Designer, `Shared/specs/parcel-v2-part2-spec.md`), narrowed where the 8.5.0 evidence below did not support the broader reading. Still behind `experimentalTools`.

### Quotes (pf2e-8.5.0)

**Loot actors cannot host Rule Elements.** `src/module/actor/loot/document.ts` lines 17-19 and 35-37:

```ts
override get allowedItemTypes(): (ItemType | "physical")[] {
    return ["physical"];
}

```

So a permanent item with Rule Elements cannot sit on a loot actor. `buildLootActorSource` already refuses such items (part 1 contract, plan 3.3.1). Part 2 applies the same rule to the offered pool, on the full document.

**Generic wands are rank r at item level 2r+1.** The pinned templates (`packs/pf2e/equipment/`):
- `magic-wand-1st-rank-spell.json`: `_id` `UJWiN0K3jqVjxvKk`, `"type": "consumable"`, `"category": "wand"`, `"level": {"value": 3}`.
- `magic-wand-3rd-rank-spell.json`: level `7`.
- `magic-wand-9th-rank-spell.json`: level `19`.

These match `WAND_TEMPLATE` in `spell-consumables.mjs`. Rank 10 has no template, so the wand level range is 3 to 19 odd.

**Attachments are not standalone items.** `flaming.json` has `"usage": {"value": "etched-onto-a-weapon"}` (level 8, traits `fire`, `magical`). `shadow.json` has `etched-onto-lm-nonmetal-armor`. Runes and reinforcing materials are equipment-type documents whose usage names the host, so `usage` starting `etched-onto` or `affixed-to` is excluded.

**Special wands are excluded by trait.** `wand-of-mercy-1st-rank.json` is `"type": "equipment"` with traits `["magical", "wand"]`. The generic wand is a consumable template built through the wand path, so the `wand` trait keeps the two apart.

**Safety traits.** `poisonous-cloak-type-i.json` carries the `cursed` trait. `Guiding Star Orb (Heroic)` (equipment, level 20) carries `intelligent`, `artifact` and `apex`, and the Keep and Philosopher's Extractor carry `artifact`. The module excludes `artifact`, `cursed`, `intelligent`, `relic`, `mythic` and `apex`, a conservative set taken from these traits, not from name matching or an AI classification.

**Mundane items.** `abysium-chunk.json` is `"type": "equipment"`, level 0, traits `["precious"]` with no magical trait. Magical trait required, so mundane items stay out (GM Core's Chapter 6 note is deferred, per the spec).

**Valuables.** `agate.json` is `"type": "treasure"`, `"category": "gem"`, `"price": {"sp": 5}`. `silk-ceremonial-armor.json` is `"type": "treasure"`, `"category": "art-object"`, `"price": {"gp": 10}`. Its id `fUENXLX3tzi33CcB` is the same one `rollable-tables/lesser-art-object.json` names as `Compendium.pf2e.equipment-srd.Item.fUENXLX3tzi33CcB`, so the SRD pack shares these document ids with `packs/pf2e/equipment`. (`packs/pf2e/equipment-srd` is not in the 8.5.0 source tree; the module reads the installed pack at runtime and skips valuables if it is absent.)

**Index fields.** The equipment index request now includes `system.traits.rarity`, so rarity is read from the index as well as from the document. Level, price, usage, traits, category and specific were already requested.

### Decisions and narrowings

1. **Rule Elements exclude the item.** The loot actor cannot host them (quote above). This is the largest narrowing: 621 of the 1252 index-eligible items.
2. **Attachments, special wands, mundane items and the non-magical types are excluded**, as the spec's deferrals require.
3. **Safety set is the trait set above.** Name matching and AI classification are not used. An item with no trait in that set is offered, and a cursed or intelligent item that lacks its trait is not caught; this is the residual risk, recorded as a gap.
4. **One valuable at most**, the first in brief order that fits the currency and passes its full document. Exact equality is allowed and leaves no coins.
5. **Coins are all-or-nothing within the remainder.** If a coin cannot be cloned, the coin remainder is dropped and reported as missing; the valuable stays, since it was built.
6. **Pp threshold 100 gp applies to the remainder** after the valuable (part 1 decision changed as above).
7. **Built value is exact.** `parcelValueGp` sums in copper and no longer rounds, so 39.95 gp shows as 39.95.
8. **A provider failure** leaves every permanent slot unfilled with the provider reason and keeps the scrolls (the spec's requirement). A cancellation rethrows.
9. **Per-level caps:** 12 equipment and 6 wands per level, and at most 36 document loads per level (3 times the 12-item cap), so the search is bounded. An item that loads but fails is skipped, not replaced.
