# Third caster archetype: Druid (conditional spec, 2026-10-30)

Base `main@129b2a1`. **Recommend Druid for a spike, not immediate availability.** None of the five candidates satisfies the requested no-GrantItem condition. Druid is the closest: fixed primal/Wisdom, one order choice and one native grant, with no required companion. It needs a new UUID-valued choice and a verified native grant path; treating it as Bard would lose the order or its consequences. Keep it unavailable until the spike and acceptance criteria pass. This recommendation relaxes the no-GrantItem criterion explicitly; it does not claim that the current machinery already supports it.

1. **UUID values and preselection:** `packs/pf2e/feats/archetype/druid/level-2/druid-dedication.json:39-55`; `src/module/rules/rule-element/choice-set/rule-element.ts:276,528` (preselection skips validation; default value is UUID). 2. **Native recursive grant:** same dedication lines 53–55; `src/module/rules/rule-element/grant-item/rule-element.ts:125-135,235,356-366` resolves the injected UUID and runs granted-item preCreate callbacks. Inspect every eligible order's rules and prove granting does not introduce unhandled choices, excess benefits, companions or duplicate items. If any cannot be handled safely, filter only with an explicit supported policy or keep the entire package unavailable; never suppress or rewrite its rules silently.
3. **Prepared access and skills:** dedication JSON line 15 specifies primal-list preparation, Nature and order skill; Basic `packs/pf2e/feats/archetype/druid/level-4/basic-druid-spellcasting.json:15` supplies no spellbook. Prove the entry does not misrepresent the accessible spell list, and the granted order implements only intended skill effects. Replacement-skill selection remains a separate gap unless the parallel work actually resolves it.
4. **Creation ordering:** `choice-set/rule-element.ts:82-87,213-228` derives the selection flag and persists the source choice; grant resolution depends on that flag. Verify ordering and resulting grant with fixtures and native acceptance. If the grant cannot be confirmed before creation or rolled back safely, block this feature.
