# Treasure parcel v3 (2026-10-29)

Branch `work/parcel-v3`, base `main@74acb07` (v0.3.5.81). Built from the Product Designer spec (`Shared/specs/parcel-v3-spec.md`), narrowed where the pinned pf2e 8.5.0 data does not establish a rule. Everything stays behind `experimentalTools`. Native rows N25–N28 are OPEN.

Pinned source: `foundryvtt/pf2e` at tag `pf2e-8.5.0`, fetched raw from `raw.githubusercontent.com` (and the sparse clone of `packs/pf2e/equipment`) on 2026-10-29. Line numbers are from those files.

## Scope built and not built

| Spec item | Decision | Why |
|---|---|---|
| Fundamental-runed weapons and armor | **Built**, ordinary bases, tiers 1 to 3 | Valuation and level match pf2e (quoted below) and each tier is verified against its document |
| Published special wands | **Built** | Equipment with the `wand` trait, exact level, no Rule Elements, safe traits |
| Up to three valuables | **Built** | Deterministic, exact copper, equality allowed |
| Vetted level-0 mundane gear for level-1 slots | **Not built (narrowed out)** | The pinned data has no chapter provenance; see "Mundane" below |
| Custom-value art | Deferred (spec) | A GM-entered value would be an arbitrary price |
| Items with Rule Elements | Deferred (spec) | Loot and merchant actors cannot host Rule Elements (quoted below) |

## Quotes (pf2e-8.5.0)

**Rune value replaces the base price.** `src/module/item/physical/helpers.ts` lines 17 to 43, `computePrice`:

```ts

    if (item.isOfType("treasure")) return item.price.value;

    // Adjust the item price according to precious material and runes
```

So with a rune, the base is `new Coins()` (zero) and the price is the rune sum alone. The +1 striking longsword is 35 gp + 65 gp = 100 gp, not 101 gp. The spec's point is confirmed. `runeGp` in `runes.mjs` sums the same rune prices, so the valuation agrees; what the helper lacked for parcels was the pinned component check and the level.

The level is the maximum of the rune levels and the base level. The rarity starts from the base rarity and takes the highest rune rarity.

**A runed item must be magical.** The early return at line 56 means a non-magical item keeps its base level. `document.ts` line 145 defines `get isMagical(): boolean { return this.system.traits.value.some((t) => t === "magical" || setHasElement(MAGIC_TRADITIONS, t)); }`. So a runed clone carries the `magical` trait. The module sets it (a module convention; N26 checks it natively).

**Shoddy.** `document.ts` line 168 to 169: `get isShoddy(): boolean { return this.system.traits.otherTags.includes("shoddy"); }`. A shoddy base is refused.

**Tier data.** `runes.ts` `FUNDAMENTAL_WEAPON_RUNE_DATA` (line 264) and `FUNDAMENTAL_ARMOR_RUNE_DATA` (line 182):
- weapon potency 1, 2, 3: level 2 / 35 gp, level 10 / 935 gp, level 16 / 8935 gp.
- weapon striking 1, 2, 3: level 4 / 65 gp, level 12 / 1065 gp, level 19 / 31065 gp.
- armor potency 1, 2, 3: level 5 / 160 gp, level 11 / 1060 gp, level 18 / 20560 gp.
- armor resilient 1, 2, 3: level 8 / 340 gp, level 14 / 3440 gp, level 20 / 49440 gp.

Each pinned document in the pack has the same level, price and rarity (common) and usage `etched-onto-a-weapon` or `etched-onto-armor`. The fixture test checks this for every tier (`tests/parcel-runed.test.mjs`).

**Special wand.** `packs/pf2e/equipment/wand-of-mercy-1st-rank.json`: `"type": "equipment"`, level 4, price 75 gp, traits `["magical", "wand"]`, `"rules": []`. It is a level-4 special wand, not a level-3 generic rank-1 wand. The generic wands are `consumable` templates at level 2r+1 (`magic-wand-1st-rank-spell.json` level 3, `magic-wand-3rd-rank-spell.json` level 7, `magic-wand-9th-rank-spell.json` level 19).

**Rule Elements.** `src/module/actor/loot/document.ts` lines 17 to 19 and 35 to 37: `allowedItemTypes` returns `["physical"]` and `canHostRuleElements` returns `false`. Items with Rule Elements stay excluded.

**Mundane.** `packs/pf2e/equipment/adventurers-pack` (AoN page 287) and the pinned documents carry `"publication": {"title": "Pathfinder Player Core"}` with no chapter or page field. The Archives of Nethys page gives a page number but no chapter, and no pinned chapter-to-page range exists in the data. Chapter 6 membership therefore cannot be established. The spec says to exclude an item whose membership cannot be established, so no mundane item is offered in v3.

## Decisions and narrowings

1. **Mundane gear not built.** No verifiable Chapter 6 provenance (see above). A future allowlist needs a pinned chapter source per entry. N25 is kept as the placeholder row.
2. **Runed items: ordinary bases only.** Weapon and armor, not specific, no existing runes, no property runes, no material, no grade, medium size, not shoddy, not magical, no Rule Elements, usage not an attachment (the breastplate has no usage field and is accepted).
3. **Runed items: tiers 1 to 3.** A secondary rune needs a potency rune. Tier 4 is not offered.
4. **Runed value and level are computed, not read.** The value is the sum of the verified tier prices in copper. The level is the maximum of the tier levels and the base level. The rarity is the highest of the base and tier rarities and must be within the Forge cap.
5. **Tiers are verified before use.** At pool time each pinned tier is read and checked against its level, price, rarity and usage. At build time the tiers are checked again with `fromUuid`. A tier that does not match is not offered, and the slot is unavailable.
6. **Create re-checks from the stored computation.** `runedSourceProblem` recomputes the value from the pinned tiers and compares it with the stored computation, the runes on the source, the magical trait, the absence of Rule Elements and the allowed level. A changed source or stored value is refused with zero writes.
7. **Special wands.** The wand trait is admitted only by `specialWandProblem`. Generic equipment still excludes it (`permanentEquipmentProblem` default). The generic 2r+1 rule does not apply to published wands. Rules-bearing wands (Wand of Widening, three Rule Elements) and mythic ones (Cyrusian Wand) are refused.
8. **Up to three valuables.** Taken in the brief's deterministic order (`rankByBrief`), each only while its exact copper value fits the remaining budget (equality allowed), each read and validated, each distinct. The coins are the exact remainder and are split by the existing coin code (pp only from 100 gp). A missing coin keeps the valuables and reports the missing remainder.
9. **Bounds.** Per level: 12 equipment, 6 generic wands, 6 special wands, 8 runed items. Runed base documents read per parcel: 12. Valuable loads per parcel: 12.
