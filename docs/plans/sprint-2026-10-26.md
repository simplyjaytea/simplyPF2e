## WP3 — Opt-in pf2e catalog drift check

**Why.** pf2e schema and content drift is the most repeated bug source in the project's history (PLAYBOOK §3 invariant 3), and every merge auto-publishes. The module hard-codes pack ids (`DEFAULT_PACKS`), `Compendium.pf2e.*` UUIDs, dedication and feat names (`pc-multiclass.mjs`), class profiles (`pc-tables.mjs`), and real-JSON fixtures. Nothing checks them against upstream.

**Change.** New `tools/check-pf2e-drift.mjs [--ref <ref>] [--json]`: derives pack-id to directory mapping from the pf2e `system.json` at the ref; verifies pack ids, UUID ids, catalog names (slug file exists, `name` and publication match), and reports fixture drift as warnings. Network-using, deliberately **not** in `tools/check.mjs`. Pure helpers exported and unit-tested offline in `tests/check-pf2e-drift.test.mjs`. One three-sentence "Drift check" paragraph in PLAYBOOK §7.

**Ownership.** `tools/check-pf2e-drift.mjs` (new), `tests/check-pf2e-drift.test.mjs` (new), the PLAYBOOK §7 paragraph.

**Acceptance.** Tool runs to completion on `master` and `pf2e-8.5.0` with full output in the report; any FAIL is reported, not patched; gate green.

## WP4 — Wizard as a complete-only Player Character class

**Research:** [wizard-research-2026-10-26.md](wizard-research-2026-10-26.md). Verdict: feasible on pf2e 8.5.0. The casting profile, base slot grid and prepared-entry shape already match the native model. Two things block it: the identity contract carries one `classPath` while Wizard has two level-1 bridges (Arcane School, Arcane Thesis), and master's Arcane School filter shape would make `stageClassPaths` skip the bridge and leave a native dialog after a one-click build.

**Decisions (orchestrator, 2026-10-26).**

1. **Scope v1:** Wizard = prepared arcane caster + closed school + closed thesis + Arcane Bond (native grant) + spellbook equal to the prepared spells (same as Cleric/Druid/Witch). Curriculum extra cantrip and extra restricted slot per rank stay **manual** (prose only in pf2e; §10 already lists curriculum slots as manual). School focus spells and familiar actors are out of v1. Text-only theses (Spell Blending, Spell Substitution, Staff Nexus) and text-only schools are offered as-is; README discloses that their effects are not automated.
2. **Per-bridge identity contract.** The single `classPath` stays for one-bridge classes (Rogue, Investigator) with no behavior change. Multi-bridge classes get one path per bridge, keyed by the bridge feature's name. `stageClassPaths` validates each bridge against its own required path; the PC editor exposes one control per bridge; the identity parser maps "school"/"arcane school" and "thesis"/"arcane thesis" to the Wizard bridges.
3. **Fail-closed guard.** After staging, any level-1 class item whose source carries a ChoiceSet but was not staged as a bridge is a hard error for complete-only classes (named error, no native dialog). This is what makes master-shaped data refuse instead of prompting.
4. **No publication allowlist** for school candidates (parity with Racket/Methodology: enabled packs only).
5. **Fixtures** are the real 8.5.0 JSON files fetched by the researcher (wizard class, the four level-1 features, two or three closed schools, one open school, the four theses, Familiar and Pet), stored under `tests/fixtures/pc-wizard/` with a README naming the URLs and ref, like `tests/fixtures/pc-backgrounds/`.
6. **Model:** Sonnet 5.5 at very high effort (escalation under PLAYBOOK §6: contract change across six modules plus a guard).

**Ownership.** `scripts/pc-support.mjs`, `scripts/class-paths.mjs`, `scripts/pc-identity.mjs`, `scripts/pc-builder.mjs` (identity validation and the `stageClassPaths` call only), `scripts/pc-edit.mjs`, `scripts/pc-editor.mjs`, `scripts/generator-app.mjs` (identity catalogs and controls only), `templates/generator.hbs` (the class-path controls only), `lang/en.json` (new keys), `tests/class-paths.test.mjs`, `tests/pc-identity.test.mjs`, `tests/pc-edit.test.mjs`, `tests/pc-editor.test.mjs`, new `tests/pc-wizard.*.test.mjs`, `tests/fixtures/pc-wizard/**`, `README.md` (the complete-only class sentence and Limitations bullets; `tests/presets.catalog.test.mjs` asserts README text, update both).

**Acceptance.** With fixtures: Wizard resolves both bridges to closed candidates and stages them; a required school plus required thesis both validate; a Rogue build with a single `classPath` is unchanged (existing tests untouched or minimally adjusted); a master-shaped Arcane School (two-entry filter) makes the Wizard build throw a named error before any write; open schools (Rooted Wisdom, Unified, Runelord) and Experimental Spellshaping are never offered; gate green; README and presets test agree.

## WP5 — Hazard generator (new generator mode, gated)

**Research:** [hazard-research-2026-10-26.md](hazard-research-2026-10-26.md). Verified: the pf2e `hazard` actor schema (only `system.attributes.ac.value` lacks a default; AC, saves and HP are raw final values; Stealth `value` is a modifier and the DC is `value + 10`); published hazards encode attacks as `melee` items (`system.bonus.value`, `system.damageRolls.<id>.{damage, damageType}`) and reactions/passives as `action` items (`system.actionType.value` = `reaction` | `passive` | `free`); the Building Hazards tables are not in the pf2e repo and were transcribed from Archives of Nethys (GM Core pg. 109, Tables 2-13 to 2-16); hazard XP uses a separate simple map (2…32) and the creature map for complex hazards; the hazards pack index exposes level, `isComplex` and traits.

**Decisions (orchestrator, 2026-10-26).**

1. **Gate.** Hazard generation ships behind `experimentalTools` (precedent: level shifting) until a native row passes. With the gate off nothing user-visible changes.
2. **Scale words** are `extreme` | `high` | `low` (the hazard tables have no moderate). Table ranges (HP, hardness) resolve to the floor of the midpoint; the Low DC range resolves to its upper value. Stealth proficiency text comes from Table 2-14 (`high` tier). These are module conventions, stated in `hazard-tables.mjs`'s header with the ORC attribution, as `tables.mjs` does.
3. **The AI emits no numbers.** It returns: `name`, plain `description`, `traits[]` (from the runtime `CONFIG.PF2E.hazardTraits` candidate list passed in the prompt), `rarity`, `complex` (boolean), `stealth` (scale or `null`), `disable[]` (`{ skill, scale }`, skills from `HAZARD_DISABLE_SKILLS`), `dispel` (boolean; the module derives the counteract rank from level, fix pass 2026-10-26), `ac` (scale or `null`), `saves` (`{ fortitude, reflex, will }`, each scale or `null`), `hasHP` (boolean), `reaction` (`{ name, trigger, effect, strike: { name, damageType } | null, save: { type, scale: extreme|high, effect } | null }`), `routine` (`{ actions: 1..3, text, strike }` or `null`; complex only), `reset`. The module renders every `@Check[...]`, `@Damage[...]` and Strike number from the tables; AI prose must pass the `reskin-policy.mjs` enricher-inert checks and is escaped with `text.mjs`.
4. **Actor source** follows the research field map exactly: `type: "hazard"`, `system.traits.{value, rarity, size: { value: "med" }}`, `attributes.{ac.value, hp.{value,max,temp,details}, hardness, stealth.{value,details}, emitsSound: "encounter"}`, `details.{description, level.value, isComplex, disable, routine, reset, publication}`, `saves.*.value` (`null` when absent). Never write derived keys (`brokenThreshold`, `hasHealth`, `initiative`, `actions`). Publication mirrors the NPC pipeline's choice in `builder.mjs`. Items: one `action` reaction (simple) or the routine's `action` plus `melee` strike (complex), shaped like `packs/pf2e/hazards/spear-launcher.json` and `spinning-blade-pillar.json`.
5. **XP.** `simpleHazardXP(level, partyLevel)` (2, 3, 4, 6, 8, 12, 16, 24, 32 for relative level −4…+4, clamped) joins `encounter.mjs`; complex hazards use `creatureXP`. Encounter-mode membership of hazards is a later package, not WP5.
6. **Crew.** H1 and H2 run on opencode free models (very high thinking) in Orca worktrees; H3a runs on Haiku 5.5 xhigh; H3b (generator-app wiring) runs after H1+H2 merge.

**API contract (binding for H1, H2, H3).**

`scripts/hazard-tables.mjs` (pure): `HAZARD_MIN_LEVEL = -1`, `HAZARD_MAX_LEVEL = 24`, `HAZARD_SCALES = ["extreme", "high", "low"]`, `hazardDC(level, scale)` (Table 2-13), `hazardProficiency(level, tier)` → `"untrained" | "trained" | "expert" | "master" | "legendary"` for tier `"high" | "moderate"` (Table 2-14), `hazardAC(level, scale)`, `hazardSave(level, scale)`, `hazardHardness(level)`, `hazardHP(level)` (Table 2-15), `hazardAttack(level, kind)` and `hazardDamage(level, kind)` → `{ formula, average }` for kind `"simple" | "complex"`, `hazardSaveDC(level, scale)` for scale `"extreme" | "high"` (Table 2-16). All clamp level to the table range and throw on an unknown scale/kind.

`scripts/hazard-builder.mjs` (pure; no Foundry globals; takes catalogs as arguments): `HAZARD_DISABLE_SKILLS` (thievery, athletics, acrobatics, arcana, crafting, deception, diplomacy, intimidation, nature, occultism, performance, religion, survival), `HazardConceptError` (with a `code`), `normalizeHazardConcept(raw, { level, traitsCatalog, damageTypes })` → validated concept (invalid optional enum picks dropped with `console.warn`; missing required fields throw), `buildHazardSource(concept, { level })` → `{ actor, items }` ready for `Actor.create({ ...actor, items })`, `describeHazard(concept, level)` → preview context (name, level, complex, stealth DC and rank, disable lines, AC, saves, HP, hardness, strike line, reaction/routine text, XP for a same-level party).

## WP6 — Scrolls and wands of real spells (Item Forge)

**Research:** [consumables-research-2026-10-26.md](consumables-research-2026-10-26.md). Verified: the native `createConsumableFromSpell` is not reachable from a module on either ref; it clones a blank rank template from `pf2e.equipment-srd` (ten scroll templates, nine wand templates, one cantrip deck; UUIDs identical on both refs), embeds `spell._source` with a fresh `_id` and `location { value: null, heightenedLevel: rank }`, unions traits (drops `magical` when a tradition is present), sets rarity from the spell, prefixes the description with an `@UUID` link, and names the item "Scroll of {name} (Rank {level})"; price and level come from the template and pf2e recomputes them on prep. The module's `buildScrollItem` already clones the template plus spell but finds the template by fuzzy name, keeps rarity common, and has no wand path.

**Decisions (orchestrator, 2026-10-26).**

1. **Mirror the native path by cloning the real templates, pinned by UUID** (invariant 2 allows cloning real documents; `system.rules` of every template is `[]`). Pin the 8.5.0 table from the research record; a fixture test compares it to the record so drift is visible. Wand rank 10 has no template, so it is refused.
2. **Rank rules (module policy, stricter than native):** `spell.baseRank ≤ rank ≤ 10` for scrolls, `≤ 9` for wands; cantrips, focus spells and rituals are refused. These match `resolveLoot`'s existing scroll rules.
3. **`buildScrollItem` migrates** to the new module so NPC loot scrolls and Forge scrolls are built by one function. Existing loot tests must keep passing; differences from the old output (rarity from spell, `@UUID` description line, native name format, embedded spell keeps a fresh `_id`) are listed in the report and in HISTORY.
4. **Forge UX:** two new `kind` tiles, `scroll` and `wand`; the brief yields up to six consumables; the AI picks only `{ spellId, rank, kind }` from a candidate list of real spells (reuse the `selectLoot` pattern); created as world items like the other Forge kinds. A Loot actor container is a later package.
5. **Crew.** C1 on Haiku 5.5 xhigh (source fidelity matters); C2 on opencode `beam-free` (very high thinking).

**API contract (binding).** `scripts/spell-consumables.mjs` (pure; takes documents as arguments): `SPELL_CONSUMABLE_TEMPLATES` (`{ scroll: { 1: uuid … 10: uuid }, wand: { 1 … 9 }, cantripDeck: uuid }`), `spellConsumableTemplateUuid(kind, rank)`, `spellConsumableRankProblem(spellData, kind, rank)` → `null` or a reason string, `buildSpellConsumable({ kind, rank, templateData, spellData })` → item source ready for `Item.create`, `spellConsumableName(kind, spellName, rank)`.
