## 1. Scope

Level shifting = produce a **new** NPC actor whose `details.level` is moved by a finite amount and whose stored numbers are moved to match the GM Core benchmark for the new level. The source actor is never modified.

Out of scope for this chunk: elite/weak (native flag, handled by C04), encounter adjustment, generation-time variants, PC paths, and any runtime change.

## 2. Verified rules

### 2.1 Book (Monster Core, "Adjusting Creatures")

Source: `https://2e.aonprd.com/Rules.aspx?ID=3262`.

- **Elite:** level +1 (+2 if the base level is −1 or 0). AC, attack modifiers, DCs, saves, Perception, and skills +2. Strike damage and other offensive-ability damage +2 (+4 for limited-use abilities such as spells or breath). HP increase by starting level.
- **Weak:** level −1 (−2 if the base level is 1). The same stat groups −2. Damage −2 (−4 for limited-use). HP decrease by starting level.
- The adjustment is not applied more than once. Larger shifts are a GM Core rebuild.

### 2.2 GM Core (Building Creatures)

Source: `https://2e.aonprd.com/Rules.aspx?ID=2874`.

- Each stat is chosen by **role** (extreme / high / moderate / low / terrible) per level. The creature's level represents its combat ability.
- Spell rank cap is half the creature level, rounded up. Innate spells are exempt from that cap.
- The level-by-level tables are the rebuild guidance. They are the benchmark owned by `scripts/tables.mjs`.

### 2.4 Stored versus derived values (measured)

- Native stores **base** values. `attributes.ac`, saves, `perception.mod`, skills, `hp.max`, Strike bonuses, and spell DC/attack are base; elite/weak is added at derivation.
- Measured on the 8.5.0 packs: the 92 NPC entries with `attributes.adjustment` set (65 elite, 27 weak) have AC, Perception, and Will residuals of median 0 against the GM Core tables at their stored level. So the stored values are base values, and a level change must shift the base values, not the derived ones.
- `classDC` is derived from the level, so setting `details.level.value` updates it automatically. Writing a DC delta on top would double count.

### 2.5 Native-vs-book divergences (record, do not extend)

- Book: "damage of its Strikes and other offensive abilities" +2. Native: first damage instance only, and the limited-use +4 exists only for spells and inline actions. Multi-instance Strikes and non-spell limited abilities are not adjusted natively.
- C04 must reproduce native elite/weak behavior, not the book text. Any wider reading is an approval item, not a C04 or C11 decision.

## 3. Operation split (design decision)

| Operation | Mechanism | Owner |
| --- | --- | --- |
| **A. Elite / weak** | Native `attributes.adjustment` flag (flat ±1 level, ±2 stats, HP table) | Native code, via C04 adapter. Unchanged. |
| **B. Level shift** | New actor. Stored base values move by the GM Core benchmark delta between level L and L+Δ. | C11 (after approval), using `scripts/tables.mjs` numbers. |

Why they are separate: the benchmark delta for one level is not the flat elite adjustment. Measured GM Core one-level deltas are about +1–2 for AC/attack/DC/saves, and an elite adjustment is a flat +2 on the same fields at the same level. Some bands show a one-level table delta **smaller** than the elite +2, so merging the two would double count or give wrong numbers. A level-shifted clone must have `attributes.adjustment` null. Applying a shift to an adjusted source is rejected.

## 4. Benchmark ownership

- **GM Core numbers: `scripts/tables.mjs`** is the only owner. C11 imports `lookup` and the exported tables. C11 must not add a second copy of any number.
- **Native elite/weak math: PF2e.** C11 must not reimplement it.
- **Hazards in `lookup()` that C11 must handle explicitly** (verified in `scripts/tables.mjs` lines 16–17, 219–227):
  1. `idx()` **clamps** the level to [−1, 24] silently. C11 must validate the source and target levels before any lookup.
  2. The default `fallbacks` are `["high","moderate","low"]`. For `SPELL_DC` and `SPELL_ATTACK` (which have only extreme/high/moderate) a `low` scale silently returns the high column. For `HP` (high/moderate/low), an `extreme` scale silently returns high. C11 must pass explicit fallbacks, and for spell tables must pass `[]` so an unmatched role fails closed.
  3. The last-resort return is the first column of the table. C11 must not rely on it.

## 5. Fit evidence (measured, read-only)

Sample: 6,335 unique NPC entries from the 8.5.0 pack JSON (`packs/pf2e/*bestiary*|*npc*|*monster*`), de-duplicated on name+level+HP. Fraction of creatures whose stored base value equals the table value for their stored level, within ±0, ±1, and ±2.

| Field (base stored value) | n | exact | within ±1 | within ±2 | median residual |
| --- | --- | --- | --- | --- | --- |
| AC | 6,238 | 77% | 98% | 98% | 0 |
| Strike attack bonus | ~6,200 | 60% | 98% | 99% | 0 |
| Spell DC | ~2,700 casters | 71% | 94% | 99% | 0 |
| Spell attack | ~2,700 casters | 60% | 87% | 93% | 0 |
| Fortitude / Reflex / Will | 6,238 | 46–48% | 99–100% | 99–100% | 0–1 |
| Perception | 6,238 | 50% | 100% | 100% | 0 |
| Skills (`skills.*.base`) | ~26,000 | 56% | 95% | 98.5% | 0 |
| HP max (`hp.max`) | 6,238 | 25% | 37% | 43% | 4 |
| Strike damage, average (nearest column) | ~6,200 | 27% | 62% | 79% | 1 |

Conclusions:

1. The GM Core columns are a good predictor for AC, attacks, DCs, saves, Perception, and skills. Gate at ±2.
2. **HP and damage are too noisy for table replacement.** Use delta-preserving transforms: `new = stored + (table[L+Δ] − table[L])`. The creature's existing residual is kept.
3. Role for stat families is the nearest column (below). The Strike attack role is the most reliable anchor for HP.

## 6. Supported range (proposal, needs approval)

- **Source level L and target level T:** both in [−1, 24]. Outside → `LEVEL_OUT_OF_RANGE`. The 5 pack NPCs outside this range are rejected.
- **Shift Δ = T − L:** supported Δ ∈ {−2, −1, +1, +2}. |Δ| ≥ 3 → `SHIFT_TOO_LARGE`; the GM Core rebuild applies. Δ = 0 is not a shift.
  - Minimal slice, if the approver wants it: restrict to Δ ∈ {−1, +1}. The algorithm is identical, so ±2 is a gate change only.
- **Source preconditions:** `type === "npc"`; not segmented (`otherSegments` / troop-type → `SEGMENTED_UNSUPPORTED`); `attributes.adjustment` is null (`SOURCE_ADJUSTED`); level value is the base.

## 7. Role classification and tolerance

For each numeric family, with stored base value v at level L:

1. Candidate columns: table columns that have a value at L. Explicit fallbacks as in §4.
2. Choose the column c* with minimal |v − table[c*][L]|. Tie → `ROLE_AMBIGUOUS`.
3. Residual r = v − table[c*][L]. If |r| > tolerance → `ROLE_UNCLASSIFIED`.
   - Tolerance is ±2 for AC, Strike attack, spell DC/attack, saves, Perception, and skills (the data in §5 keep ≥93% of creatures).
   - Strike damage: compare averages; tolerance ±2 average points.
   - HP: no tolerance. HP role is the **primary combat role**, i.e. the c* of the first Strike attack bonus. HP residual is preserved, so no HP gate.
4. New value: v + (table[c*][T] − table[c*][L]). The new value is computed from the **same** column, so a round trip Δ then −Δ returns the original value exactly.

Estimated eligibility on the pack sample (martial, measured):

- 3,288 unique NPCs with no spellcasting entry, at least one melee Strike, unadjusted, level in range.
- **2,357 (72%)** pass every gate in §7 (AC, saves, Perception, skills, Strike attack ±2 of nearest column; Strike damage average ±2 of nearest column).
- 273 NPCs have no melee Strike entries and are rejected (`NO_STRIKE`).
- 2,677 are casters (handled in §9).

## 8. Field mapping

| Field | Family | Rule |
| --- | --- | --- |
| `details.level.value` | level | Set to T. |
| `attributes.ac.value` | AC | Delta, §7. |
| `saves.{fortitude,reflex,will}.value` | saves | Delta, §7, per save. |
| `perception.mod` | Perception | Delta, §7. |
| `skills.*.base` and Lore items' `system.bonus.value` | SKILL | Delta, §7, per skill. Lore is treated as a skill. |
| Melee items' `system.bonus.value` (Strike attack) | Strike attack | Delta, §7. |
| Melee items' first damage instance (`damageRolls`) | Strike damage | If the formula string equals the table string at L for c*, replace with the table string at T. Otherwise keep the dice and shift the flat modifier by integer Δavg (Δavg = avg(table[c*][T]) − avg(table[c*][L])). Non-integer Δavg or negative resulting modifier → `DAMAGE_UNSUPPORTED`. Other damage instances are unchanged, matching native first-instance behavior. |
| `attributes.hp.max` | HP | Delta with the primary-role HP column, §7. The new max is the stored base; `hp.value` = new max (fresh clone, no adjustment). |
| `attributes.adjustment` | — | Must be null on the clone. |
| `spellcastingEntry` `system.spelldc.dc` / `value` | spell DC / attack | Delta from `SPELL_DC` / `SPELL_ATTACK` using §7 with **no fallbacks**. A role that does not match an existing column → `SPELL_ROLE_UNCLASSIFIED`. |

**Exclusions (unchanged on the clone):** ability modifiers (`abilities.*.mod`), resistances/weaknesses/immunities, traits, speed, reach, senses, items other than the above (treasure, equipment), spell items' ranks and names, spell slots, focus pools, innate use frequencies, limited-use pools, and images/token. Exclusions are listed in the preview.

Abilities are excluded because the stored totals (skills, attacks) already carry them and the GM Core ability table is not used for totals in this design. This is a design choice `[INFERENCE]` on whether an approver wants abilities shifted.

## 9. Caster policy

Proposal: **narrow**. Casters are supported only when every condition holds; otherwise reject.

1. Spell DC/attack shifted from the spell tables (§8), with no fallbacks.
2. No spell item with damage (`system.damage` non-empty). Spell damage is not rescaled in v1 because no benchmark for spell damage exists in `scripts/tables.mjs` and the native spell damage rule is rank/heightening-dependent. Reject → `CASTER_DAMAGE_SPELL_UNSUPPORTED`.
3. Prepared, spontaneous, and focus spells: rank ≤ ceil(L_target / 2). Level ≤ 0 → reject `CASTER_LEVEL_UNSUPPORTED` (cap at L ≤ 0 needs explicit confirmation).
4. Innate spells: unchanged and exempt from the cap (GM Core).

Measured on the pack sample (2,723 caster entries after de-duplication):

- 1,925 (71%) have at least one damaging spell item → rejected in v1.
- 790 have no damaging spell item before rank and DC gates.
- 57 creatures have a non-innate spell rank above ceil(L/2) (heuristic count) → rejected at that level.
- 456 creatures have innate ranks above the cap. This is allowed (exempt).

So v1 casters are a minority. A caster-damage design is a separate approval item; it is not needed for martial shifts.

## 12. Pure-policy and C11 test plan

C11 adds a pure module (proposed name `scripts/level-shift-policy.mjs`) with no Foundry globals, plus Foundry wiring in a separate file. Tests (stub Foundry; no live world):
