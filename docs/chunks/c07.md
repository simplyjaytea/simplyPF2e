## General archetype rules (Player Core pg. 215, 8.5.0 journal)

1. Archetype feats replace class feats in the class-feat slots. Take a dedication as a class feat, then any archetype feat whose prerequisites are met. Archetype class feats follow the restrictions of the class feat they replace.
2. Dedication lock: you cannot select a different dedication until you have completed the current one by taking two other feats from that archetype. You cannot retrain a dedication while any other feat from that archetype is held.
3. Multiclass archetype: a dedication cannot be taken if you are already a member of that class.
4. Additional feats: feats from other sources can be taken as archetype feats at the listed level; the class trait is dropped; they count toward the dedication.
5. Feats that grant feats: the granted feat must meet prerequisites; the granting feat and the grant count as one feat (for example Basic Fury → Sudden Charge counts as one).
6. Special archetypes (Player Core 2 pg. 174): skill-trait archetype feats may replace a skill feat, and a skill feat still counts toward the dedication. Class archetypes are chosen at level 1, change abilities at level 1, take the dedication as the second-level class feat, and at most one may be held.
7. Spellcasting and bounded spellcasting archetypes (magus, summoner are bounded): excluded initially.
8. Archetype Artifacts: one artifact at a time; invested artifacts cannot be removed. Alchemical Archetypes: advanced-alchemy and Quick Alchemy grants. Both excluded initially.
9. Temporary items last until the next daily preparation.

## Free Archetype (GM Core pg. 84)

- Extra class feat at level 2 and every even level after it, usable only for archetype feats. The GM may restrict it to a theme or leave it unrestricted.
- The normal dedication lock (rule 2) still applies unless the GM chooses to ignore it.
- Playing advice: cap feats that scale with archetype feat count (multiclass Resiliency) at half the character level.
- Repo mapping: the free slot is the existing `archetype-<level>` location. Ordinary archetype feats use normal class-feat slots at the same levels.

## Dedication lock design

State is derived from the actor's feat items, not from flags:
- `currentArchetype`: the package of the held dedication, or none.
- `otherCount`: held feats of that package other than the dedication.
- New dedication D allowed only if `currentArchetype` is none, or `otherCount ≥ 2` for the current package (grant + granter counts once; skill feats count).
- Retraining is blocked while any non-dedication archetype feat of the current package is held.
- Dedication D blocked if D's class equals one of the PC's classes (rule 3).
- Non-dedication archetype feat from package P requires P's dedication held and its prerequisite met. Fighter/Rogue/Investigator PC classes make Dedication of the same class invalid.
- Class archetypes (level-1 class archetype trait) are a separate single slot and excluded from the lock.
- Free slots use the same lock unless the GM waives it. The GM waiver is not implemented initially.
- Resiliency cap (GM Core guidance): recommended ceiling of `floor(level / 2)` for multiclass Resiliency feats. Recommended as a validation warning, not a hard block; coordinator decision.

## Boundary classes (grant, resource, choice)

- **Native rule elements (grant/effects):** Fighter, Rogue, Investigator, Barbarian, Monk, Ranger dedications and feats use GrantItem, FlatModifier, AdjustModifier, Strike, Resistance, RollOption, ActiveEffectLike. The module copies items; the system applies rule elements. The module must not reimplement these effects.
- **Grants to compendium items only:** GrantItem UUIDs point into the system compendium (e.g., Rage, Hunt Prey, Surprise Attack, On the Case, Devise a Stratagem, Flurry of Blows, Reactive Strike, Sneak Attack). Module may allow only UUIDs that already exist in the pack.
- **Resource grants (unavailable initially):** any grant to focus pools, spellcasting, companions, Quick Alchemy, Panache, Ikons, Innovations, Kinetic Impulses, Implements, Way/martial graphs.
- **Native ChoiceSets (system prompt):** dedications and several basic/advanced feats use ChoiceSet with system filters, e.g.:
  - Basic Fury/Maneuver/Trickery/Kata/Hunter's Trick/Deduction: `item:category:class`, same trait, `lte item:level 2`.
  - Barbarian instinct (`item:tag:barbarian-instinct`); Fury Instinct gives a level-1 barbarian feat ChoiceSet; Elemental Instinct and Dragon Instinct use flagged ChoiceSets.
  - Rogue Dedication skill choice: Stealth or Thievery (rank); Rogue skillFeat ChoiceSet: `item:trait:skill`, `lte` self level.
  Open: whether the system prompts automatically when the item is embedded, or whether the module must preset `flags.system.rulesSelections`. Not verified in this slice.
- **Text-only choices (module-side picker needed):** Advanced Maneuver (Fighter), Advanced Trickery (Rogue), Advanced Deduction (Investigator) have no rule elements. The description says "You gain one <class> feat" with prerequisites evaluated at half character level and "You can select this feat more than once". No native prompt exists; C08 must provide an explicit picker or leave the slot unresolved with a warning. Advanced Kata (Monk) and Advanced Hunter's Trick (Ranger) follow the same pattern [INFERENCE; not checked this slice].
